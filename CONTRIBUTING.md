# Contributing

1. Create a scoped branch from `develop` or the current integration baseline.
2. Keep domain behavior inside the appropriate package instead of duplicating constants across apps.
3. Run `npm run verify` before requesting review.
4. Never claim an external submission, payment, permit, license, certificate or approval without evidence.
5. Changes to regulated training, payment, identity, security or database migrations require explicit review.
6. Promotion follows feature → develop → qa → staging → release → main.
